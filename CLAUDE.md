# The Facility

Dark-comedy Android app. **V.E.R.A.** — a deadpan, faux-supportive AI administrator — owns the whole screen. She is a live model woken by the subject's own API key, she keeps two files, and she has opinions about you. React Native + Expo (TypeScript), Android-first, bilingual en/ko.

**Read first:** `design/The Facility - Overhaul.dc.html` — **the v2 prototype, and the authority on every pixel.** The spec below is a *derivation* of it and is wrong in places (it gives module tiles a 12px radius; the design uses 14px). Implementation target is turn **4a** (the live prototype — its own runtime lives in a `<script type="text/x-dc">` block near the end, holding the `EM` emotion table and `applyEmotion`), with the optic from turn **3a**, since 4a's stage eye carries no lid at all. Sections are `<section class="dv-turn" id="tN">`, options `<div class="dv-opt" id="4a">`.

Pulled from Claude Design project `bc25a219-1ba4-4fef-9978-f21c0e6596dd` ("Overhauling VERA's design") with the `DesignSync` tool. **`list_projects` will not show it** — that method filters to design-system projects and this is a plain one; go straight to `get_project` / `list_files` / `get_file` with the UUID.

Then: `docs/superpowers/specs/2026-07-30-overhaul-design.md` (the v2 spec — every section number cited in code comments points here) · `docs/architecture.md` (stack, structure, mechanics) · `design/The Facility.dc.html` (the v1 prototype; still the source for Module 01's terrarium, but its enrollment/daily screens are gone).

**The hover rule.** The prototype is a web page and states several controls twice — a resting colour and a `style-hover` one. A touch screen has no hover, so every such pair is resolved to the **hover** value (see the note at the top of `src/core/theme.ts`). Don't "fix" these back to the resting colour.

## The shape of it

**The four stimuli (2026-08-12).** She is purely reactive and answers exactly four things. Only **`subject_spoke`** reaches the model — context is assembled, `runSpeech` runs, and the finished exchange is queued for extraction. The other three — **`open`** · **`activation`** · **`subject_tapped_your_optic`** — are answered from the authored bank in `src/vera/bank.ts`: no network, no context, no extraction, no `thinking` state. Both paths share one tail (transcript, typewriter, `saveSoul`), the key guard and the re-entrancy guard; only the live path touches the `authFails` tally. Erasing the transcript, switching language and feeding the specimen are silent actions now — she is told about none of them. `bank.ts`'s tables and its `pick()` are **placeholders awaiting the real bank**; nothing outside that file changes when they are replaced.

**Her words live in a window, at one size (2026-08-31).** `Splash + Response Window.dc.html`, turn **3a** — which is 2b with the optic returned to 158. Her line used to sit loose on the stage under the emotion label, sized by a ladder that ran 30px down to 15px on word count. It now sits in a bordered window (`panelAlt`, radius 14) that takes the height left under the eye, headed by a **status strip** carrying the pulsing iris dot, her emotion label, and one live word: **TRANSMITTING** while the typewriter is still drawing, **COMPLETE** once it stops. Both come off `shown.length < line.length` — nothing new is stored to know she is mid-sentence, and the same comparison drives the blinking amber caret after her last drawn character.

`fluid.ts` is **gone**; `voice(lang)` in `theme.ts` replaces it with the ladder's own bottom rung (en 15 / ko 14, through `ms()`). One size, because a size that moved under her fought the frame around it, and because SOUL.md holds her to under 30 words — which at this size arrives whole. The ScrollView stays as the safety net for a keyboard-up or an over-long reply, not as the normal case. Three states the design's own runtime does not cover are decided here: `thinking` reads as TRANSMITTING, a stage where she has never spoken shows **no** status word (a third word would be copy the design does not have), and under a `systemNotice` the status is blank — reporting COMPLETE beside the app's own red line would claim, in her colour, that she said the thing she never got to show. With nothing to hold, the window **collapses to its strip** and the optic row takes the slack, so the dormant screen keeps the centred eye it has today and the gate keeps its room.

**The splash is the launcher icon enlarged, and rotates with it (2026-08-31).** Turn **4** is nine splashes, one per face — and every value it lists (iris, glow, aperture, pupil, lid, blink) is already in `emotions.ts`, so `Splash.tsx` draws no new geometry: it is `<Optic size={234}/>` on `palette.iconBg` #131011 with the wordmark at `bottom:54`. The face comes from **`faceFor(Date.now(), hasKey)`** — the launcher's own decision function, same two inputs — so the two cannot drift, `hasKey` gates before the day, and `faceEmotion` maps 'Calm' → 'calm' with a dormant fallback so a name added to `faces.json` with no emotion behind it costs a dead eye rather than a crash on the first frame.

The native splash is a build-time PNG and cannot follow the rotation, so `app.json` ships **`icon-fg-dormant.png` at `imageWidth: 390`** (the PNG is 432² with the optic at 60%, so 390 × 0.6 = the same 234 the JS splash draws) and `App.tsx` calls `preventAutoHideAsync()` at module scope to hold it. `hideAsync()` fires only once fonts **and** hydration are done, then the JS splash holds the day's face for 900ms. Hydration is what settles `hasKey`, and `hydrate()` writes `apiKey` and `hydrated` in one `set()`, so the frame the splash becomes visible on is already the right face — the JS splash renders before that, unseen behind the native one. Two consequences the design names and we accept: a launcher still caching yesterday's icon disagrees for one launch, and the native-to-JS size match depends on `imageWidth` not being clamped on a narrow device.

**Views:** `stage` · `log` · `sys` · `mem` · `soul` · `mod01` · `mod02`. **Overlays:** the cabinet drawer and the ACCESS key panel — both owned by `ScreenRouter`, both sitting on top of whatever view is showing.

**Android hardware back** (`stepBack()` in the store) is one step out, never a jump: an open overlay closes first and the view stays put · `mem`/`soul` → `sys` · `sys`/`log`/`mod01`/`mod02` → `stage` · on `stage` it returns `false`, which is the signal to let the OS exit.

**The doorway rule (spec §4).** Modules are rooms in her building, not screens in her app. The shell owns exactly four things: the tile (identical geometry in the cabinet, painted in the module's own colours), full bleed inside, one exit (top-left, 44px, drawn in the module's own ink — never the shell's amber), and her dot. Everything past the threshold belongs to the module. A new module is **one folder exporting a `ModuleDef` plus one line in `registry.ts`** — both `Cabinet.tsx` and `ScreenRouter.tsx` read the registry, neither names a module.

**The six stores (spec §8).**

| store | key | engine | contents |
|---|---|---|---|
| soul | `facility.v2.soul` | AsyncStorage | visits, day, lastOpen, lang, cleared |
| transcript | `facility.v2.transcript` | AsyncStorage | the chat log, capped at 60 |
| memory | `facility.v2.memory` | AsyncStorage | facts, verdicts, threads, pending |
| module 01 | `facility.mod01.organism` | AsyncStorage | hunger, hungerAt |
| module 02 | `facility.mod02.identity` | AsyncStorage | title, lines, revs, month |
| credential | `facility.v2.credential` | **SecureStore** | the key |

Modules 01 and 02 each own their own store — neither has anything to do with her soul or the transcript, and she is not told what is in either. Hunger used to live in the soul store because she was told about it; it moved out with the specimen (2026-08-12). `cleared` survives in the soul store for one reason only: the RECORD screen's `erasures: N` line. She is never told the number.

**Nothing named MEMORY.md exists any more, and no file backs either view (2026-08-25).** There are two renderings of one store, deliberately named apart because they differ in content: the **RECORD** screen (`buildMemoryMd` in `FileScreen.tsx`) shows the whole record at render time — facts, verdicts, threads, expired and resolved ones marked but never hidden — while **what she is given** (`composeMemoryMd` in `memoryDoc.ts`, headed `# WHAT YOU KNOW ABOUT THIS SUBJECT`) carries only the narrower selection: `selectMemories` takes unresolved threads first, oldest five (the longest-unanswered), under 30 days old, uncharged, then pools facts and verdicts by score into a 3000-character budget. The heading is exported as `MEMORY_HEADING` and named in exactly one place; `speak.ts` introduces the section by description, and SOUL.md names no document at all, so renaming it again touches one constant. Neither view is markdown on disk — the only stored thing is `facility.v2.memory`, a JSON blob. **SOUL.md is read-only** and is the literal system prompt, not a paraphrase of it. The transcript is the only thing the subject can erase — via CLEAR → ERASE ALL on the LOG screen, the app's one delete — and erasing it costs her the wording, never the verdict. **Erasing files nothing (2026-08-25, reversing spec §4.4).** It used to append a `v_erasure` verdict whose count escalated; that treated the subject's own housekeeping — a clean context, a smaller token count — as an act against her. She is told nothing at the time and nothing afterwards, her record comes through byte-identical, and the pending queue survives so exchanges already spoken are still read.

**The five accepted key shapes (spec §9), order significant** — every `sk-` shape below also satisfies OpenAI's pattern (its class includes the hyphen, and 32 hex digits are alphanumerics), so anthropic, openrouter and deepseek must all be tested before it:

| label | pattern | model |
|---|---|---|
| ANTHROPIC | `^sk-ant-` | `claude-sonnet-5` |
| OPENROUTER | `^sk-or-` | `anthropic/claude-sonnet-5` |
| DEEPSEEK | `^sk-[0-9a-f]{32}$` | `deepseek-chat` |
| OPENAI | `^sk-(proj-)?[A-Za-z0-9_-]{20,}$` | `gpt-4o-mini` |
| GOOGLE | `^(AIza\|AQ\.)` | `gemini-2.5-flash-lite` |

Groq was dropped (2026-08-07); the spec's §9 table still lists all six and is out of date on this point and on the Gemini rows below.

**Model ids are a live dependency, on every route (2026-08-28).** Both Anthropic routes moved from `claude-sonnet-4-5` to `claude-sonnet-5` ahead of the former's **29 Sep 2026** retirement; OpenRouter proxies to Anthropic, so it retires with it. A retired model **404s**, which is neither an auth refusal nor a quota failure, so she falls back to authored lines indefinitely and looks alive. Tests pin the id on all three live routes for exactly that reason — they are the only thing that catches it before a subject does.

**Two Gemini gotchas, both live.** Google is migrating keys from `AIza` (standard) to `AQ.Ab…` (auth, service-account-bound): AI Studio issues **only** the new form now, and from **September 2026** the API rejects standard keys outright — so a gate matching only `^AIza` refuses every key a subject can currently create. And `gemini-2.0-flash` is **shut down**; `gemini-2.5-flash-lite` is the replacement and is the one 2.5 model with **thinking off by default**, which matters because a thinking model would spend the 300-token budget on thoughts and return no text. `llm.ts` also filters out response parts marked `thought` so reasoning is never spoken as her line. A retired model 404s rather than 401s, so it never raises `AuthError` — she just falls back to an authored line forever and looks alive. A test pins the model id for that reason.

**Her states are named to her, and her turns are replayed in the envelope (2026-08-31).** Two prompt bugs, found together and fixed together, both invisible to the suite before they were.

*She was always calm.* The system prompt ended `Return ONLY minified JSON: {"emotion":"<one of your states>","line":"<your reply>"}` and **nothing ever listed the states** — not `speak.ts`, not SOUL.md, which only forbids her reciting them. So she invented a word every reply (`wry`, `neutral`, `dry`), `isEmotionKey` recognised none of them, and `parseSpeech` clamped every one to `calm`. Eight states shipped, one was ever seen. `SPEAKABLE_EMOTIONS` in `speak.ts` now names them in the prompt, derived from `EMOTIONS` so a ninth state is offered without a second edit; `dormant` is filtered out because it is the app's dead grey, not hers to choose. The clamp stays as the safety net it was meant to be.

*She dropped the JSON on the second message.* `buildMessages` replayed her past turns as the bare line, so the conversation was a worked example of ignoring the JSON instruction — and an example in the messages outweighs an instruction in the system prompt. She complied on the first reply (no assistant turn yet) and answered in plain prose on the second, which `parseSpeech` cannot read, so a perfectly good line was thrown away and an authored fallback shown instead. It compounded: every turn added another demonstration. Her turns now go back as `{"emotion":…,"line":…}` via `composeSpeech`, deliberately beside `parseSpeech` — what one writes is what the other reads. A merged same-role run is **one** envelope holding both lines (two objects glued with `\n` is not JSON), the state she ended the run in wins, and a `dormant` fallback replays as `calm` so the transcript never demonstrates a state the prompt forbids.

**Both documents in the system prompt are fenced (2026-08-31).** The prompt is one flat `join('\n')` of two markdown documents and a handful of loose instructions, and two seams were invisible in it. SOUL.md's last section is `## Memory`, so the sentence introducing her record read as one more paragraph of it; and nothing closed the record at all — the instructions after it sat directly under its `## Unanswered` heading like more items in the list. `fence()` in `speak.ts` now wraps each document in `=== BEGIN <label> === / === END <label> ===`, and the five trailing instructions sit under one `=== HOW TO REPLY ===` header instead of floating. The record's label is derived from `MEMORY_HEADING` rather than restated, so `memoryDoc.ts` stays the one place that section is named. **`===`, not `---`, is deliberate:** the PROMPT screen wraps its own sections in `--- SECTION ---`, and a prompt using the same rule would be unreadable on the one screen built to read it — there is a test pinning that. The fences are static text, so SOUL.md remains the stable cache prefix. `buildExtractPrompt` already did this correctly with bare `CURRENT FILE` / `RECENT EXCHANGES` headers; this brings the speak prompt up to it.

**What the subject types is data, and so is what she said (2026-08-31).** Both prompts interpolated untrusted text at column 0 with the app's own lines following it. `buildUserPrompt` put their words inline after `THE SUBJECT SAYS:` and then wrote its instructions and `CONTEXT:` underneath, so a pasted newline was enough to add lines indistinguishable from the app's. `buildExtractPrompt` replayed the transcript as `THEY: …` / `YOU: …`, so a message beginning `YOU:` could forge her half of an exchange. `quoted()` in `fencing.ts` now prefixes every line of both with `> ` — nothing untrusted reaches column 0, so nothing untrusted can pass for a label, a fence or an instruction — and the extraction labels moved onto their own lines, since a label sharing the first line of quoted content was the one part of a turn still open to impersonation. Their words arrive **intact**, not stripped: she answers what they actually typed, the attempt included.

**This is not a security boundary and the code says so.** It is their key, their device and their conversation, and there is nobody on the other side to protect from them. What it protects is the **record**: extraction is the app's only call that writes to disk, so a forged turn is the only kind that persists — and once a verdict is drawn from something she never said, it is fed back to her on every reply afterwards. Everything else this stops (a second `CONTEXT`, a closed fence, an instruction to drop the character) is the milder and more recoverable version of the same trick.

**Her record is dated, and the rule is about invention rather than numbers (2026-08-31).** Every entry has always carried a timestamp — `Fact.at`, `Verdict.firstAt`/`at`, `Thread.at` — and `composeMemoryMd` stripped all of them, so she was given "reached 2 times" with no *when* while SOUL.md told her to cite her records because "a conclusion you have written down is a finding". Ordered to cite and handed nothing to cite, she invented the when: observed 2026-08-31, knowing only that this was return number five today, she said "You asked that this morning too" about a morning that never happened.

`composeMemoryMd(selection, now)` now stamps every entry `YYYY-MM-DD HH:MM` and opens with `It is now …`, because absolute dates are worth nothing against a present she does not know — CONTEXT gives her a time of day and no date at all. Stamps are in the **device's timezone**, not UTC: she is talking to someone about their morning, not filing a report (its tests derive the expected string rather than hardcode one, or they would pass here and fail in another zone). A verdict reached more than once carries **both** ends of its life — twice in a day and twice a month apart are not the same finding. The call site takes `Date.now()` once and hands the same instant to `selectMemories` and to the document, so the two cannot straddle a minute boundary and disagree inside one prompt.

The prompt rule changed with it. `Do not open a reply with a number, a count, or the time` forbade the very citation SOUL.md asks for, so it is gone; in its place she is told to cite a date or a count whenever it earns the line and **never to invent one** — if the record does not say when, she does not know when. SOUL.md is untouched: its own restraint about numbers is scoped to "facts about your situation" (the CONTEXT counts), which is craft about not sounding like a stats readout, and is unrelated to citing her record.

**One accepted consequence: the selection budget now under-counts.** `BUDGET_CHARS` (3000) charges `entry.text.length` only — never the bullet, the `(reached N times)` suffix, the headings, or threads at all — so it was always an approximation. The stamps add roughly 19 characters per entry that it does not model, so a record large enough to hit the cap renders longer than the cap suggests. Left alone deliberately: charging for them would silently make her remember fewer things, which is a bigger change than adding dates and was not what was asked for.

**The PROMPT screen is the debugging surface, and is meant to be pasteable whole (2026-08-31).** It carries both calls — her reply and the extraction that follows it — and every field exists because something was once indistinguishable without it. Beyond the request itself: `emotion` is the state **after** the clamp, read against the emotion inside the raw reply (the two differing is the clamp firing, invisible anywhere else); `spoke` is the line the subject actually saw, and under a notice it says the app took the turn and prints the line she never got to show; `took` separates a 25s timeout from a slow provider from an instant refusal; `--- RAW REPLY (N chars, COULD NOT BE READ) ---` puts the verdict in the header and the length beside it, which is the only clue to a reply cut off by the 300-token budget — valid text that stops mid-object. **Text on the file screens is `selectable`**, so a screenshot is not the only way off the phone. What it still does not hold: **only the last exchange of each kind**, so a failure two messages back is gone, and no provider `finish_reason` (deliberate — surfacing it changes `callLlm`'s return type and every mock of it, and the char count answers the same question).

**An empty 200 is a failure, and extraction has its own budget (2026-08-31).** `callLlm` used to return the empty string when a 200 carried no text, so the caller read it as a model that had answered unreadably — on the PROMPT screen, `RAW REPLY (0 chars)` and nowhere further to go. Two real failures land there: **OpenRouter returns some upstream errors as HTTP 200** with an `error` object and no `choices` (the explaining sentence was being discarded by a reader looking only for text), and a response that spends its whole budget before emitting content. Both now throw, carrying the provider's own sentence where there is one and otherwise the finish reason — `stop_reason` · `finish_reason` · `native_finish_reason` · `finishReason`, so every route is covered. Nothing about `callLlm`'s return type changed; the reason travels in the thrown message into `failure`. And extraction no longer shares the reply's 300-token default: `EXTRACT_MAX_TOKENS` (1000) is passed on the request **and stated in `EXTRACT_SYSTEM` from the same constant**, because a ceiling the model is told about but not given would make it record less for nothing. The two calls were never the same job — a reply is under thirty words, extraction rewrites a file covering the whole pending queue (capped at 40) — and a merely tight ceiling became impossible as that queue grew: every failure leaves more to write up on the next attempt against the same limit, a loop that cannot escape on its own.

**Why a call failed is recorded, and two failures speak in the app's own voice (2026-08-28).** `callLlm` reads the provider's error body and throws it — `http <status>: <the provider's own sentence>` — so `PromptRecord.failure` and `ExtractRecord.failure` carry a reason and the PROMPT screen prints it under `--- NO REPLY ---`. Before this, `raw: null` was the whole story and an exhausted account, a retired model and a dead socket were one indistinguishable line. `SystemCode` is now `'auth' | 'quota'`: a **401/403** is the credential's fault and marks a row under ACCESS, while a **402, or a 400/429 whose body names a credit balance or `insufficient_quota`**, is the account's — the key is valid, so `authFails` is untouched and the wording says to add credit rather than replace the key. A plain 429 rate limit is deliberately *not* quota: it is transient and nothing the subject can fix. Everything else stays hers, covered by an authored line.

Anything under 8 characters, containing whitespace, or matching none of the five is refused at the gate. The accepted consequence: a **valid** key from an unlisted provider (Mistral, Together, xAI, Groq) is refused. Requests go straight from the device to the matched provider — there is no server in this project. A key on the device is readable by anyone holding the phone; it is the subject's own.

## Conventions & gotchas

- All copy verbatim from `T` in `src/shell/strings.ts` (and each module's own `strings.ts`); all hex from `palette` in `src/core/theme.ts`. Don't "improve" either, and don't add strings the design doc doesn't have.
- Verify with `npm test` and `npx tsc --noEmit`. Jest is pinned to 29 (jest-expo 57 requires it); RTL v14 is fully async (`await render(...)`, `await fireEvent.press(...)`, **`await view.unmount()`** — omitting that last one causes overlapping `act()` and `toJSON()` returning null); jest uses the `react-native-worklets/jest/resolver.js` resolver.
- **No test may make a real network request.** Mock `src/vera/llm.ts` with a `jest.requireActual` spread so `AuthError` stays a real class for `speech.ts`'s `instanceof`, and mock `expo-secure-store` with an in-memory vault (the OS keystore has no jsdom implementation).
- Skia can't run in jest (jsdom); it's mocked as a no-op Proxy in `jest.setup.ts`. **Never put logic inside a Skia component** — it is invisible to tests. Skia now carries two things: the optic (`Optic.tsx`, continuous animation) and Specimen-03's blob (`modules/organism/Blob.tsx`).
- **Two builds, side by side (2026-08-28).** `app.config.js` overlays `app.json` and reads `EAS_BUILD_PROFILE`: the **development** profile builds `com.youngmookk.thefacility.dev` named "V.E.R.A. dev", everything else builds the shipping id. Both install at once, with separate data. Unset — a local prebuild, `expo run:android`, Metro — defaults to the **shipping** identity on purpose: a local build landing on the installed app is an annoyance, a cloud build going out under `.dev` is a wrong package id no later build can take back. `--profile development` needs `npx expo start` running to load any JS at all; `--profile preview` bundles the JS in and runs anywhere, at the price of a rebuild for **every** change. Either way, a native dependency, an `app.json` change or an SDK bump needs a rebuild.
- **`expo-secure-store` is native and the two new fonts are new assets, so a dev build installed before 2026-07-30 cannot load v2.** The one on the phone is current. Build another with `npx eas-cli@latest build -p android --profile development`, and expect to need one whenever a native dependency moves. **The deferred patch bumps were taken on 2026-08-19** (expo 57.0.14, react-native 0.86.2, reanimated 4.5.1, worklets 0.10.1, expo-dev-client 57.0.13, expo-splash-screen 57.0.7, jest-expo 57.0.4), so **the dev build on the phone predates them and needs replacing** — five of the seven are native. `npx expo install --fix` **cannot do this update**: it installs in two passes, and the second fails ERESOLVE because `react-native@0.86.2` peer-wants `@react-native/jest-preset@0.86.2` while `jest-expo` — which is what actually governs that peer, and which the fixer leaves at its old range in `package.json` — still pins 0.86.0. Do not take npm's suggestion of `--force`/`--legacy-peer-deps` (see `.npmrc` below). The fix is to let `--fix` write `package.json`, then `rm -rf node_modules package-lock.json && npm install` for a single clean resolve. Profiles live in `eas.json` (Android APK, `internal` distribution, node pinned 24.14.1). Run with `npx expo start` (auto-detects `expo-dev-client`).
- **After a React Native version bump, build with `--clear-cache` or the APK will crash on launch.** The 2026-08-19 build was made from the correct commit with a correct lockfile (RN 0.86.2) and still died two seconds in, silently, with nothing in the Metro terminal. `adb logcat -b crash -d` gave the cause: `libworklets.so` aborting on `jsi::Value::getString(): assertion "isString()" failed`, with the header path reading **`react-android-0.86.0`**. EAS's Gradle cache had compiled worklets against the *old* react-android prefab while `npm ci` installed the new React Native — an ABI mismatch, so worklets read a `jsi::Value` with the wrong memory layout. `npx eas-cli build -p android --profile development --clear-cache` fixed it. **`npm test` and `tsc` cannot see this class of failure at all** — Skia and reanimated are jest no-ops, so nothing in the suite touches worklets' native side. A real build on a real device is the only detector.
- **`expo-notifications` is gone**, along with `@react-native-community/slider`. There are no notifications, no permission ceremony, and no background work of any kind in v2 — the daily loop that justified them was deleted.
- **`.npmrc` (committed) pins `legacy-peer-deps=false`** — a global `~/.npmrc` with legacy-peer-deps=true silently drops `@react-native/babel-preset` + its metro/hermes peer subtree from the lockfile, which breaks EAS Build's strict `npm ci`. Keep it; don't regenerate the lock with legacy-peer-deps on.
- No navigation library (conditional render on `view` **is** the router), no raster UI assets, fonts bundled locally (no CDN).
- Repo style is single quotes. An editor formatter here has previously reformatted files to double quotes — don't let it.
